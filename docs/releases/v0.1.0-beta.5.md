# ProcLens 0.1.0-beta.5

Fifth public beta. ProcLens shows what Windows Task Manager leaves out: where all your memory
goes, which programs and files are really hitting the disk, how much CPU your drivers use, and what
your network adapters and open ports are doing.

**This is a beta, and it has been tested on exactly one PC** (Windows 10 Home 22H2, build
19045.7725, x64). Please read "Before you run it".

## What's new since 0.1.0-beta.4

This is a small release: **the program itself is unchanged** (the app, the collector and the
protocol between them are the same code as beta.4). Only the installer changed.

- **Start menu:** the installer now puts ProcLens in a Start menu folder called **aity**
  (Start > aity > ProcLens), next to the other aity apps, instead of a top-level ProcLens folder.
  The shortcuts inside are the same (ProcLens, README, Release notes, Check this PC (discover),
  Uninstall). Upgrading removes the old top-level ProcLens folder. README and FAQ say
  **aity > ProcLens** where they point at the Start menu.

How it was checked: the installer was built from the tagged commit and tested as an upgrade over
beta.4 on the one test PC (version, shortcuts, removal of the old folder, launching the installed
app). Nothing else was re-tested, because nothing else changed.

## Before you run it

- **One tested machine.** Windows 11, other Windows 10 builds, other editions and other hardware are
  untested. On a build it doesn't know, ProcLens says so ("Untested Windows build"), labels its event
  tables as a best guess, and runs built-in self-tests whose results appear on the **This PC** tab; a view whose
  check failed also shows a warning. (Only the memory breakdown turns itself off automatically; the
  other views keep running.) You may still see wrong or missing numbers. If you do, that is exactly the feedback this beta is for.
- **The disk, files and driver views need administrator approval.** The window itself runs as a normal user.
  Reading kernel-level data needs a separate small helper, `collector.exe`, which the app starts through the
  usual Windows approval prompt each time. The helper only reports data; it cannot end, change or inject
  into other programs. Click **Stop collector** to end it; if the app goes away without that, it exits by
  itself after about 30 seconds. (Closing the window is meant to stop it too, but that path has not been
  tested.) The Overview, Network, Ports and Connections pages and both logs' network parts need no approval.
- **The connection log records who your PC talks to.** It is off until you switch it on, it stays on
  this PC, and nothing is looked up or sent anywhere, but the file lists remote addresses next to program
  names. Switch it off, or delete the files, when you share your PC or the log folder.
- **Where you unzip it matters.** The app starts `collector.exe` from its own folder with administrator
  rights. If that folder is writable by ordinary programs, anything running as you could swap in a
  different `collector.exe` and have it elevated when you approve the prompt. For real protection put the
  folder somewhere only administrators can write, such as `C:\Program Files\ProcLens`.
- **The files are unsigned.** Windows SmartScreen will warn about them, and security software may object
  to a tool that enables debug privilege and reads the system handle table. The development PC has
  Bitdefender installed and the locally built copies ran without being blocked; I can't see its logs, and
  I have not scanned the downloadable zip.
- **Needs the Microsoft Edge WebView2 runtime**, which is normally already installed.

## Install

**Installer (recommended).** Download `proclens-0.1.0-beta.5-windows-x64-setup.exe`, check its SHA-256
against the value below, and run it. It asks for administrator approval and installs to
`C:\Program Files\ProcLens` (all users; there is no per-user option, for the reason given above), adds
ProcLens to the shared **aity** folder in the Start menu (Start > aity > ProcLens), plus a desktop shortcut, ticked by default; untick it to skip) and an uninstaller
under Apps & features. Then start ProcLens; click **Start collector** and approve the prompt for the disk, file
and driver views. The setup file is unsigned, so SmartScreen will warn about it too.

**Portable zip.** Download `proclens-0.1.0-beta.5-windows-x64.zip`, check its SHA-256, extract it (see
the note above about where), run `proclens-app.exe`, click **Start collector**, approve the prompt.

## What it does

- **Overview:** the summary and tiles described above.
- **Memory:** every byte of RAM split into in use, modified, standby cache and free, with where the "in
  use" part sits.
- **Disk & files:** per-process physical disk traffic and file requests, disk response time, and the
  busiest files. The trace runs only while this tab (or Drivers) is open, or while the activity log is on.
- **Drivers:** CPU time each driver spends handling hardware interrupts, which Task Manager folds into
  "System".
- **Network, Ports, Connections:** as described above.
- **This PC:** your exact Windows build, whether it has been verified, and the result of each live
  self-test.
- **Command line:** `collector.exe profile` (build and self-tests), `collector.exe discover` (run
  elevated: works out this build's event tables from the live system and compares them with the
  profile), plus `mem`, `procs` and `etw` dumps.

## Known limitations

- **The connection log can miss short connections.** It compares readings taken every 5 to 60 seconds
  (10 by default); a connection shorter than that may fall between two readings, and start and end times
  are only as exact as the interval. It records no bytes per connection or program. Sessions still open
  when the app crashes are lost (switching the log off, or closing the window, writes them out; the
  window-close path has not been tested). How many lines a day it writes has not been measured: check the
  folder after a day before relying on the 28-day and 256 MB limits.
- **Ports and Connections:** the reserved port ranges come from `netsh`, and only English output was
  checked. The IPv6 UDP table layout was tested against hand-built data only. A connection listed twice
  by Windows is shown twice. The "services inside a process" lookup was checked on one PC, where nearly
  every `svchost.exe` hosts a single service; on a PC with less memory Windows groups more services into
  one process and you will see "one of N services" more often.
- **The `traffic` lines count every network adapter that is up, including traffic to other machines on
  your own network** (a media stream, a backup), not only the internet.
- Driver CPU times are estimates: on the tested PC they landed within roughly 14-27% of Windows' own
  counters for DPC time and within about 27% for interrupt time. Disk response time is converted with the
  machine's performance-counter rate and looked plausible on SSDs, but was not checked against an
  independent timer.
- Some file traffic cannot be tied to a file name (files opened before tracing that no longer have a
  readable handle): under 1% in the last run on the tested PC. Expect it to vary with what your PC is doing.
- Some of what ProcLens reads (the memory page lists, the system handle table, one interrupt event type)
  is undocumented by Microsoft and can change in a Windows update. Each is guarded by a runtime check,
  but a future update could still make those checks fail. `docs/REFERENCES.md` lists exactly which
  documentation covers what.
- On GitHub's Server 2025 images the driver DPC/ISR view reported zero: the events are emitted but their
  schema does not resolve there. Whether a real Windows 11 or Server 2025 PC does the same is not known.
- No auto-update, no code signing. With the app open, setup and the uninstaller ask you to close it. If
  the collector is still running when you uninstall or upgrade, Windows may ask to close it or defer
  removing `collector.exe` to the next restart; click **Stop collector** first.
- A file handle that is closed and reused between the moment the handle table is read and the lookup
  can give one file the wrong name. It is a wrong label for that file only.
- Uninstall leftovers: on the one PC tested, after an uninstall an empty `C:\Program Files\ProcLens`
  folder and the WebView2 cache folder `%LOCALAPPDATA%\uk.aity.proclens` were still present. They are
  safe to delete by hand. The uninstaller does not list your log files in `%LOCALAPPDATA%\ProcLens\logs`
  for removal (read from the installer script, not tested), so delete them yourself if you want them gone.
- The `discover` command's calibration thresholds were tuned on one machine.
- Licensing: `THIRD-PARTY-NOTICES.txt` lists the 255 Rust crates and 4 JavaScript packages in the
  binaries with their licence identifiers, followed by the full licence texts shipped in each package
  (157 distinct texts, grouped so identical ones appear once). Six crates ship no licence file in their
  archive; for those the text comes from the upstream repository (or, for `selectors`, the standard
  MPL-2.0 text, since its repository has none), as recorded in `docs/licenses/README.md`. Five
  unmodified crates are MPL-2.0 (cssparser, cssparser-macros, dtoa-short, option-ext, selectors); their
  source is at the repositories named in that file.

## Feedback

Open an issue at https://github.com/anubisalpha/proclens/issues. The most useful thing you can attach
is the output of `collector.exe profile`, and, on a Windows build other than 19045, an elevated
`collector.exe discover`. `profile` shows your Windows build and patch level, whether it matches a
verified profile, the result of each self-test, and the quirks recorded for that profile, and it also
describes the machine the profile was verified on (not yours). `discover` prints event types and field
names only. With the installer, run them from `C:\Program Files\ProcLens`; see the README.

Everything in this release was built from the tagged commit with `tools/package-release.ps1`.
